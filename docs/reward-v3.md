# Reward v3

Reward v3 是面向约束购物任务的确定性终局奖励。它依据环境证据评价 Agent 实际选择的
商品，不使用另一个语言模型判断答案。

## 1. 编译任务要求

Rollout 开始前，任务与目标商品元数据会转换为固定特征：

- 商品类别和价格上限；
- 指令中明确提到的品牌别名；
- 指令与目标元数据共同包含的型号标识；
- 必须满足的核心功能；
- 颜色、尺寸、容量、套餐等必选规格。

这些要求会在策略开始行动前冻结，策略无法修改后续评分依据。

## 2. 应用硬门槛

一次购买必须同时满足：

- **类别：**所选商品属于要求的类别。
- **预算：**所选规格的最终价格不高于用户预算上限。

硬门槛失败会返回 `wrong_purchase`，奖励为 `-0.85`。如果环境证据不足以验证硬门槛，
则返回 `reward_unverifiable`、奖励 `0.0` 且 `reward_valid=false`。该零奖励不视为成功
的中性结果。

## 3. 计算偏好得分

只在当前任务启用的维度中计算以下四个软约束：

| 维度 | 权重 |
|---|---:|
| 品牌 | 0.35 |
| 型号 | 0.25 |
| 核心功能 | 0.25 |
| 关键规格 | 0.15 |

匹配得分为：

```text
S = Σ(weight_i × score_i) / Σ(active weight_i)
```

证据覆盖率按同一组有效权重汇总。完全满足要求时，匹配得分和覆盖率都必须为 1.0。

## 4. 映射终局奖励

| 结果 | 奖励 |
|---|---:|
| 精确命中目标 ASIN，且满足全部要求 | `1.00` |
| 选择其他 ASIN，但满足全部要求 | `0.55` |
| 部分满足的替代商品 | `min(0.25, -0.30 + 0.55 × S)` |
| 充分搜索后合理停止 | `-0.15` |
| 未充分搜索便停止 | `-0.35` |
| 达到 35 步上限 | `-0.50` |
| 重复或无进展循环 | `-0.65` |
| 类别错误或超预算 | `-0.85` |
| 缺少必需证据 | `0.00`，无效 |

精确命中目标称为 `gold_purchase`；不同商品只要通过相同硬门槛并完全满足全部有效偏好，
就称为 `valid_alternative_purchase`。这样可以避免把单一商品 ID 当作唯一正确答案。

## 5. 合理放弃与终止

只有在 Agent 查看至少两个有效结果集、打开至少两个候选商品，并且没有已知合格候选时，
停止才算合理。硬门槛均通过、偏好匹配不低于 0.70、证据覆盖不低于 0.75 的候选视为
“已知合格”。

以下情况也会终止轨迹：

- 连续两次完全相同的动作；
- 连续四次动作没有带来新的运行时证据；
- 总步数达到 35。

搜索结果、新打开的商品、详情子页、已选规格和约束检查都会计入证据。证据次数设有上限，
避免 Agent 无限刷取进展。
