## 摘要

基于大语言模型的 Agent 正越来越多地用于电商购物。为了完成充分且面向个人的商品搜索，Agent 需要理解用户偏好、进行多轮对话，并最终从高度相似的商品中检索和辨别正确目标。然而，既有研究尚未提供一个同时覆盖这些能力的统一模拟环境，而且往往只关注评测基准，缺少训练支持。

论文提出 **ShopSimulator**：一个大规模、高难度的中文购物环境。作者使用它评测多类 LLM，发现即使表现最好的模型，完全成功率也低于 40%。错误分析表明，Agent 在长轨迹中的深度搜索与商品选择方面表现不佳，难以恰当地利用个性化线索，也不能有效地与用户沟通。进一步的训练实验显示，监督微调（SFT）与强化学习（RL）的组合能显著改善表现，并给出如何缓解这些问题的实践依据。代码和数据发布于 <https://github.com/ShopAgent-Team/ShopSimulator>。

## 1. 引言

现代电商平台中，个性化、可交互的商品搜索已经成为用户体验的关键组成部分。现实用户给出的目标常常模糊、不完整，甚至在对话过程中发生变化。一个有效的购物助手不应只匹配显式查询，还要主动澄清目标，从用户画像与历史行为中推断偏好，再从大量相似商品中检索、比较并选出最合适的产品。

LLM 将交互、推理和搜索统一在同一工作流中，因此很适合成为下一代购物助手。与 SFT 或 DPO 等离线方法不同，PPO、GRPO 等强化学习算法依赖 Agent 在交互环境中自主探索，再利用反馈信号迭代策略。WebShop、DeepShop 等工作已经推动了电商环境探索，但仍存在两个缺口：

1. 缺少一个同时覆盖个性化、多轮交互和细粒度商品辨别的统一环境。
2. 多数工作主要用于评测，对训练资源和 RL 策略探索支持不足。

论文围绕两个研究问题展开：

- **RQ1：** 当前 LLM Agent 在带个性化偏好与多轮交互的环境里表现如何，能否成为可靠的购物助手？
- **RQ2：** 在这种环境里，哪些训练策略能把 LLM 推向更可靠的购物 Agent，尤其是 RL 相比 SFT 有何作用？

ShopSimulator 使用真实商品和接近真实用户的特征构造中文电商沙盒。Agent 需要通过多轮对话澄清意图，搜索并浏览商品，根据属性与用户偏好推理，最终购买最合适的商品。数据包含淘宝 12 个领域的 130 多万件商品；每个细分类目都保留大量高度相似商品，迫使 Agent 先做粗粒度召回，再做细粒度辨别。

用户建模方面，环境使用 LLM 扮演购物者，并为其提供包含长期偏好、人口属性和历史购买模式的详细画像。任务覆盖单轮、多轮、非个性化和个性化场景，每个任务都提供类目、属性、规格和价格等多维奖励信号。

论文的主要贡献是：

1. 构建同时支持训练和评测的中文购物沙盒，包含大规模商品库、个性化多轮用户模型和细粒度商品区分。
2. 系统评测先进 LLM，证明它们距离可靠购物助手仍有明显差距，并通过错误分析定位薄弱环节。
3. 在 Qwen3-8B 上比较 SFT、RL 和 SFT+RL，验证 SFT 与 RL 的互补性以及严格奖励的优势，同时揭示多轮个性化任务仍然困难。

## 2. ShopSimulator

### 2.1 任务形式化

WebShop 一类环境把购物建模为序列决策过程。Agent 在文本购物界面中完成一个固定、明确的目标 `G`。时刻 `t`，策略 `πθ` 根据当前观察 `o_t` 和目标生成动作 `a_t`，环境 `E` 再返回下一观察：

```text
a_t = πθ(o_t, G)
o_(t+1) = E(o_t, a_t)
```

动作包括文本检索、浏览搜索结果、查看商品详情和购买。完成购买或达到最大步数后，当前 episode 结束。

ShopSimulator 在此基础上增加三项能力：

1. **多轮交互：** LLM 模拟的用户只逐步透露信息，Agent 必须主动澄清不充分或含糊的目标。
2. **个性化：** 策略可访问结构化用户画像及历史行为，需要把偏好纳入搜索和选择。
3. **细粒度商品辨别：** 每个最小子类约有 120 件高度相似商品，不能依靠随机命中。

多轮、个性化设置下，策略还依赖当前用户话语 `u_t` 与静态画像 `p`：

```text
a_t = πθ(o_t, u_t, p)
o_(t+1), u_(t+1) = E(o_t, a_t)
```

多轮模式把“直接向用户提问”纳入动作空间；个性化模式提供画像 `p`。环境也保留不带画像的单轮与多轮场景。

### 2.2 环境构建

构建流程包括三阶段：商品目录收集、任务生成和用户建模。

#### 商品目录

作者在获得平台授权的前提下，使用 **2025 年 6 月淘宝快照**。先按曝光频率选出 5,000 万件高频商品，再移除子类过少的一级类目。GPT-4o 用于判断类目复杂度与类内多样性：低复杂度类目被剔除，低多样性类目被降采样。

为了保证细粒度辨别，每个子类保留约 120 件高频且相似的商品，形成约 2 万件商品的高质量集合 **Catalog-Fine**。之后从其余合格商品中再抽取约 130 万件，形成覆盖更广的 **Catalog-Full**。

#### 任务构造

每条自然语言购买指令与整个目录中的唯一商品一一对应。标注者根据商品标题、类目、店铺、规格、属性和价格撰写指令，但不能直接照抄标题或核心关键词，而要使用同义词、描述性短语、风格表达或日常说法。最后再检查是否存在另一件相似商品也能完整满足指令。

Catalog-Fine 最终构造约 24K 个任务。只有“非个性化单轮”场景把完整指令直接作为用户输入；多轮场景的目标会由用户与 Agent 在多次交互中共同表达。

#### 个性化

个性化任务给每条任务增加结构化用户画像，包括年龄、性别、消费层级、品牌偏好等用户信息与长期偏好。画像里的长期需求会从指令中移除，只保留颜色等本次商品特有线索，避免 Agent 只从对话文本中推回完整要求。

因为真实画像涉及隐私，作者先由 LLM 生成画像草稿，再由人工审核、修改和丰富，同时避免画像对目标商品过拟合。特别具体的属性仍保留在任务指令中。最终得到 **4,726 个个性化用户画像及相应改写指令**。

#### 多轮交互

LLM 模拟的购物者一开始只表达模糊意图，只有在 Agent 提问后才逐步透露必要属性。若 Agent 在信息不完整时准备购买，购物者应拒绝。该设置要求 Agent 主动发现并补齐信息缺口，然后才能购买。

### 2.3 奖励

若只在全部条件满足时给 1、否则给 0，学习信号会过于稀疏。论文因此同时定义宽松加法奖励与严格乘法奖励。

设目标要求包括类目 `U_cat`、属性集合 `U_att`、规格集合 `U_opt` 和价格上限 `U_price`；购买商品对应 `Y_cat`、`Y_att`、`Y_opt` 和 `Y_price`。

#### 宽松加法奖励

在类目软匹配分数 `R_cat` 的基础上，对属性、规格和价格的满足情况取平均：

```text
R_loose = R_cat ×
          (|U_att ∩ Y_att| + |U_opt ∩ Y_opt| + 1[Y_price ≤ U_price])
          / (|U_att| + |U_opt| + 1)
```

它允许不同维度相互补偿：某项不满足，其他项得分仍可能把总分抬高。

#### 严格乘法奖励

严格奖励采用“短板式”乘法：

```text
R_strict = R_cat
           × |U_att ∩ Y_att| / |U_att|
           × |U_opt ∩ Y_opt| / |U_opt|
           × 1[Y_price ≤ U_price]
```

任一必要维度为 0，总分都会显著降低或归零，因此更强调完整满足全部约束。

#### 完全成功率

评测还报告 `R_succ`：一次 episode 只有在购买商品的所有必需维度都与目标完全一致时记为 1，否则为 0。它衡量“完整成功”，不能由部分匹配补偿。

### 2.4 数据统计

环境覆盖四种场景：

1. 单轮（Single-Turn）
2. 多轮（Multi-Turn）
3. 个性化单轮（Single-Turn & Pers）
4. 个性化多轮（Multi-Turn & Pers）

28K 任务进一步划分为训练集和评测集。Catalog-Fine 覆盖所有任务所需目标商品。由于 Catalog-Full 带来更高资源消耗和延迟，论文后续训练与评测实验统一使用 Catalog-Fine。

12 个领域分别为：家居生活、工业与农资、休闲娱乐与教育、运动户外与出行、美妆个护与健康、家电与电子、食品饮料、服装鞋饰、母婴儿童、本地与综合服务、在线服务与数字商品、二手与拍卖。

## 3. 评测

### 3.1 设置

- 单轮任务最大动作数：30。
- 多轮任务最大动作数：40。
- 多轮购物者模型：Qwen3-225B-A22B。
- 指标：`R_loose`、`R_strict` 和完全成功率 `R_succ`。

### 3.2 主要结果（原表 2）

下表保留最便于比较的 `R_succ`；完整表还报告宽松和严格奖励。

| 模型 | 单轮 | 个性化单轮 | 多轮 | 个性化多轮 | 四场景平均 |
|---|---:|---:|---:|---:|---:|
| GPT-5 | 40.78 | 36.41 | 29.29 | 24.13 | **32.65** |
| OpenAI o3 | 33.72 | 26.73 | 31.19 | 22.31 | 28.48 |
| GPT-4.1 | 29.13 | 27.85 | 23.17 | 23.83 | 25.99 |
| Claude-4-Sonnet | 30.29 | 32.17 | **38.25** | 25.39 | 31.52 |
| Gemini 2.5 Pro | 29.24 | 32.76 | 29.10 | 27.13 | 29.55 |
| DeepSeek-R1 | 25.27 | 29.19 | 29.27 | **30.30** | 28.51 |
| DeepSeek-V3.1 | 31.86 | 35.69 | 31.62 | 28.07 | **31.81** |
| Qwen3-235B-A22B | 27.96 | 26.81 | 24.29 | 23.60 | 25.66 |
| Qwen3-30B-A3B | 20.88 | 22.84 | 10.04 | 17.18 | 17.73 |
| Qwen3-32B | 19.67 | 23.99 | 3.67 | 14.36 | 15.42 |
| Qwen3-8B | 14.13 | 17.24 | 6.48 | 13.63 | 12.87 |

数字单位为百分比。闭源模型中 GPT-5 的总体成功率最高；开源模型中 DeepSeek-V3.1 的总体成功率最高。

#### 总体观察

所有模型的完全成功率都较低。即使 GPT-5 的四场景平均 `R_succ` 也只有 32.65%。`R_loose` 普遍远高于 `R_strict` 和 `R_succ`，说明许多推荐只满足类目或部分属性，却没有满足全部细粒度要求。

#### 多轮任务

模型在多轮环境中普遍退化，说明它们难以在长上下文中持续追踪状态、主动澄清并理解不断补充的意图。小模型退化更明显：Qwen3-8B 从单轮到多轮时，严格奖励下降约 47%，成功率下降约 50%；Qwen3-235B-A22B 的相应降幅约为 13% 和 14%。

把个性化单轮与非个性化多轮相比，多数模型，尤其是小模型，在前者表现更好。这说明持续澄清比读取静态偏好约束更困难。

#### 个性化

加入个性化信息并不总会提升表现。它一方面能提前缩小搜索空间、减少重复澄清和无效探索，另一方面也会增加上下文噪声；模型可能把偏好误当成硬约束。真正困难的是平衡“充分利用”和“不过度解读”。

### 3.3 错误分析

作者从 Claude-4-Sonnet 的失败轨迹中人工归纳错误类型，再使用 GPT-5 对全部轨迹分类。

#### 动作层错误

- **搜索：** 忽略关键属性 15.04%，放弃高匹配结果 8.74%，重复相似查询 8.67%。
- **点击：** 违反硬约束 12.25%，未确认关键属性 2.74%，点击不存在按钮 2.35%，重试已被拒绝的属性 0.80%。
- **购买：** 45.63% 的错误来自未确认重要细节就购买，31.31% 来自用户拒绝后仍购买；两者合计接近 80%。
- **询问用户：** 信息缺失却不询问占 9.40%，重复确认已知信息占 2.40%，用户已告别仍继续询问占 0.70%。

总体上，Agent 会在检索时忽略关键属性或浪费已有候选，在商品选择时弱化硬约束，在购买前缺少确认，导致成功率下降且轨迹变长。

#### 个性化错误

- 未充分利用画像信息：55.82%。
- 过度解读画像信息：35.71%。
- 混淆本次短期目标与长期偏好：8.79%。

个性化失败的根源不是单纯“画像用得少”，而是模型没有正确区分显式硬约束、当前意图和长期软偏好。

#### 模拟购物者错误

购物者侧错误总体低于 8%。其中包括额外增加意图 3.69%、扭曲目标意图 2.93%、不回答关键目标 0.43%。因此，整体低成功率的首要原因仍在 Agent 侧。

## 4. 强化学习探索

### 4.1 训练设置

作者针对四种场景分别训练 Qwen3-8B，比较两条路线：

1. 直接在 Qwen3-8B 上做 RL。
2. 先用 SFT 冷启动，再做 RL。

SFT 数据来自 GPT-4.1 在训练集上产生的 6K 条成功轨迹。RL 使用 ROLL 框架和 GRPO 算法，分别尝试 `R_loose` 与 `R_strict`。详细超参数见附录 D：

| 项目 | 设置 |
|---|---|
| SFT 基座 | Qwen3-8B |
| SFT 数据 | GPT-4.1 的 6K 条成功轨迹 |
| SFT batch size | 32 |
| SFT 学习率 | 1×10⁻⁵ |
| SFT epoch | 4 |
| RL 框架 / 算法 | ROLL / GRPO |
| RL KL loss | 省略，以鼓励探索 |
| 最大上下文 | 32K tokens |
| RL 学习率 | 1×10⁻⁶ |
| RL 总步数 | 200 |
| 每步采样 | 32 个样本，每个样本 8 条轨迹 rollout |

### 4.2 训练结果（原表 3）

以下为完全成功率 `R_succ`：

| 场景 | 基线 | SFT | RL + 宽松奖励 | RL + 严格奖励 | SFT + RL + 严格奖励 |
|---|---:|---:|---:|---:|---:|
| 单轮 | 14.13 | 32.47 | 28.07 | 30.19 | **38.89** |
| 多轮 | 6.48 | 29.27 | 18.64 | 22.32 | **35.50** |
| 个性化单轮 | 17.24 | 30.98 | 32.98 | 38.37 | **57.33** |
| 个性化多轮 | 13.63 | 30.49 | 28.44 | 28.29 | **34.35** |

#### SFT 与 RL 的分工

所有训练方法都显著优于基线，且 **SFT + RL + `R_strict`** 在四类场景均最优。提升主要来自属性和规格匹配改善。

没有工作流先验时，RL 很难自主探索，尤其是在多轮任务中。SFT 可以直接模仿成功轨迹，因此单独 SFT 在非个性化单轮和多轮上优于单独 RL。与此同时，SFT 容易继承教师模型较长的成功轨迹；RL 自主探索出的轨迹往往更短、更简洁。

SFT 更擅长学习任务流程和动作模式，RL 则能通过多次 rollout 发现并优化个性化偏好。加入个性化后，RL 与 SFT 的差距缩小；在个性化单轮中，单独严格 RL 的成功率甚至比 SFT 高 7.39 个百分点（论文正文用严格奖励综合分比较时报告 +8.25%）。这解释了为什么先 SFT 冷启动、再用 RL 优化效果最好：前者降低探索难度，后者补足偏好理解和细粒度匹配。

#### 严格奖励优于宽松奖励

四个场景中，以 `R_strict` 作为 RL 目标都比 `R_loose` 更有利于总体匹配和成功率。乘法奖励会把注意力集中到属性、规格等最弱维度；加法奖励则更容易鼓励覆盖面或“完成动作”，但不够强调最终准确性。

#### 场景差异

单轮和个性化单轮的训练收益更大，因为模型较容易学习完整执行流程并利用静态画像。多轮和个性化多轮要求模型在长轨迹中协调画像理解、澄清对话与环境动作。即使训练后，成功率仍只有约 35%。

## 5. 相关工作

### 5.1 电商 LLM Agent 评测

部分工作评测 LLM 的电商概念知识和推理能力，另一些工作评测模型模拟用户行为的能力。ShopSimulator 关注的是：LLM 能否在环境中综合完成完整购物任务。

WebShop 首先建立了购物交互环境；ChatShop、DeepShop、WebMall 和 ShoppingBench 分别扩展到多轮对话、深度商品搜索、跨店浏览和优惠券使用。但这些环境主要依赖英文商品语料，且通常缺少个性化或训练支持。ShopSimulator 的区别是提供大规模中文电商沙盒，并同时支持个性化、多轮和训练。

### 5.2 电商 LLM Agent 训练

相关路线包括领域适配、对话式多 Agent 推荐、多模态购物客服、将 LLM 接入推荐管线，以及通过 RL 模拟人类购物行为。ShopSimulator 提供大量训练任务与多维奖励信号，论文则系统比较了 SFT、RL 以及 SFT 冷启动后再做 RL 的效果。

---

## 6. 结论

ShopSimulator 把大规模真实商品目录、多轮个性化用户模型、评测任务和训练支持统一到一个中文购物沙盒中。评测显示，即使强 LLM 也远未达到可靠购物助手的水平。主要失败来自细粒度属性/规格 grounding 不足以及不理想的交互行为。SFT 与 RL 的组合可以部分缓解这些问题，但多轮个性化仍是明显短板。

---

## 7. 局限

1. 用户画像是 LLM 合成并经人工修订的，分布可能偏离真实用户。
2. RL 实验虽然覆盖多种场景与设置，但主要使用 GRPO，未系统比较更新的 RL 算法。
3. 环境只处理文本交互，没有纳入真实电商中的商品图片和视频。

## 8. 伦理声明与潜在风险

### 伦理声明

- 商品数据经电商平台授权收集，遵守当地法律与平台政策，不包含个人隐私信息。
- 中文标注者均为中文母语者，至少拥有本科学历；报酬根据任务耗时和难度制定，高于当地最低工资要求。标注过程在线完成，不涉及身心伤害。

### 潜在风险

- 商品目录来自 2025 年 6 月快照，可能带有时间和平台特定分布，分布变化时表现可能不均衡。
- 合成画像可能包含偏见或不完整偏好，导致不同用户群体上的表现不均衡。
- 指令依赖人工撰写与审核，主观差异和一致性漂移可能产生轻微标签噪声。

## 9. 附录要点

### 9.1 Agent 系统提示词的核心约束（原图 7）

Agent 被要求：

- 收集商品类型、预算、属性偏好和规格需求。
- 使用 `search[keyword]` 与 `click[value]` 和环境交互。
- 购买前选择好规格，并确认商品完整满足用户需求。
- 信息缺失时先提问；信息充分时才操作环境；每轮只能执行一个动作。
- `click[buy now]` 表示立即购买，不是进入结算页。
- 点击值必须来自当前页面可用按钮。
- 若用户拒绝或提出新信息，不得购买。

原始提示词还带有“对话结束前必须购买当前最合适商品”等强制终止规则。这类规则能提高完成率，却也可能诱发论文错误分析中观察到的草率购买，需要结合严格确认机制理解。

### 9.2 模拟购物者提示词（原图 8）

模拟购物者持有一个仅自己知道的具体目标，一开始只给模糊意图；它应自然回答 Agent 的问题，不主动一次性透露全部细节。购买前若仍有信息未传达，购物者应拒绝并给出简单理由，等待 Agent 继续询问。

### 9.3 商品、任务与画像示例（原图 9–11）

论文使用一双 YONEX 羽毛球鞋示范三者如何对齐：

- 商品包含真假保障、减震、耐磨、男女同款等属性，以及白蓝配色、40 码等规格，价格 528 元。
- 任务用自然语言要求宽楦、正品、减震耐磨、白蓝、男女同款、40 码和 550 元预算。
- 个性化画像进一步提供 YONEX 高品牌偏好、40 码、蓝白色、运动消费倾向以及近期搜索行为。

### 9.4 三类轨迹示例（原图 12–16）

- **单轮：** 用户一次给出完整条件。Agent 搜索、打开 YONEX 商品、选择白蓝配色和 40 码，然后购买。
- **多轮：** 用户逐次补充预算、尺码、蓝白配色、宽楦、男女同款和精确型号。Agent 多次搜索和确认后购买目标商品。
- **个性化多轮：** 初始观察包含结构化画像。Agent 从品牌、尺码、价格区间、功能与近期搜索中推断软偏好，再结合用户当前话语执行搜索。

这些示例说明：同一个商品目标可被改写成不同信息披露方式，从而分别测试固定指令执行、主动澄清和画像利用。

### 9.5 奖励分量的计算细节（附录 C.3）

- **类目分量：** 检查初始查询是否相同、类目路径是否至少共享两个节点、标题关键词重叠率是否超过 0.2。任一条件满足时系数为 1.0；否则为 0.5，标题相似度低于 0.1 或为 0 时进一步降为 0.1 或 0。
- **属性分量：** 计算目标语义属性中有多少能在商品属性中匹配；使用模糊字符串匹配，若属性列表中找不到，还会检查标题与详情描述。
- **规格分量：** 用模糊匹配计算颜色、尺码、容量等目标规格的满足比例。
- **价格分量：** 商品价格不超过预算上限记 1，否则记 0。

## 10. 对本项目的直接启示

1. **不要把“完成购买动作”当作成功。** 必须区分终止、类目匹配、属性匹配、规格匹配、价格满足和完整成功。
2. **SFT 先教流程，RL 再调策略。** 对工具协议复杂、搜索空间大的购物 Agent，直接 RL 的探索成本很高。
3. **Reward 要保护短板。** 可被其他维度补偿的加法奖励容易掩盖严重失误；关键硬约束需要不可补偿的门控或乘法结构。
4. **购买前核验是独立能力。** “找到候选”不等于“选对规格”，更不等于“可以购买”。
5. **多轮需要专门设计。** 单轮提升不能直接外推到多轮；状态记忆、澄清策略、用户拒绝后的回退都需要单独评测。
6. **画像应分成硬约束与软偏好。** 当前明确要求优先于长期偏好，避免过度个性化。

> 注意：本仓库当前采用自己的 ShopSimulator Environment v2.1、Reward v3、observation v2 与 tool schema v2。论文结果用于理解上游方法，不能与本仓库的单轮 Final-200 指标直接横比。
